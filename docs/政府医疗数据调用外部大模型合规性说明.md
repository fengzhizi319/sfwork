# 政府医疗数据经分类分级与隐私处理后调用外部大模型——合规性说明

> **文档定位**：面向项目决策层、安全合规部门、数据控制方（卫健委/医保局等），论证“政府医疗数据 → 分类分级 → 剔除高敏感数据（四川L4/L5等价子集）→ 保留数据脱敏匿名 → 调用外部大模型获取康养建议”这一技术路线的合规性。  
> **适用标准**：DB51/T 2989—2023《四川省健康医疗大数据应用指南》、GB/T 43697-2024《数据安全技术 数据分类分级规则》、GB/T 35273-2020《信息安全技术 个人信息安全规范》  
> **上位法依据**：《中华人民共和国数据安全法》（2021）、《中华人民共和国个人信息保护法》（2021）、《中华人民共和国网络安全法》（2017）  
> **编写日期**：2026年8月

## 一、业务流程概述

```
政府医疗数据（原始）
    │
    ▼
┌─────────────────────────────────────────┐
│ 第一步：数据分类分级                       │
│ 依据 DB51/T 2989—2023 五级分类标准        │
│ 自动识别 L1~L5 敏感等级                   │
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│ 第二步：数据筛选与剔除                     │
│ ✗ 剔除四川L4等价数据                      │
│   （敏感病种：HIV、精神病、癌症等）         │
│ ✗ 剔除四川L5等价数据                      │
│   （基因/遗传信息）                       │
│ ✓ 保留一般健康状况数据                     │
│   （高血压、糖尿病、慢病等常见病症）         │
│ ✓ 保留 L1~L3 数据                        │
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│ 第三步：本地隐私处理（数据不出域）           │
│ • 脱敏：身份证号/手机号/姓名 → 掩码/哈希     │
│ • K-匿名：年龄/邮编 → 区间泛化（k≥5）       │
│ • 差分隐私：统计指标加噪（ε≤1.0）           │
│ 处理后数据降级至 L1/L2                     │
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│ 第四步：调用外部大模型                      │
│ 将脱敏匿名后的非敏感数据发送至               │
│ DeepSeek / 通义千问等大模型                │
│ 获取老人康养建议                           │
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│ 第五步：结果输出与审计                     │
│ • 大模型返回康养建议（非个人数据）           │
│ • 全流程审计日志留痕                      │
│ • 隐私预算台账记录                        │
└─────────────────────────────────────────┘
```

**核心主张**：发送到外部大模型的**不是原始医疗数据**，而是经过分类分级筛选（剔除高敏感病种与基因信息）、脱敏匿名处理后**已不构成个人信息**的低敏感度数据。保留的一般健康状况数据（如高血压、糖尿病等常见慢病）经去标识化处理后，仅以统计级/泛化形式参与大模型推理。

## 二、合规性法律依据

### 2.1 上位法支撑

| 法律法规 | 相关条款 | 对本流程的支撑 |
|---|---|---|
| 《数据安全法》第21条 | 国家建立数据分类分级保护制度，根据数据重要程度和危害程度实行分类分级保护 | 本流程严格执行分类分级，按级别采取差异化保护措施 |
| 《数据安全法》第27条 | 开展数据处理活动应当建立健全全流程数据安全管理制度 | 本流程具备完整的审计日志、隐私预算台账、参数治理体系 |
| 《个人信息保护法》第4条 | 个人信息是以电子或其他方式记录的与已识别或可识别的自然人有关的各种信息 | **经脱敏+K-匿名处理后，数据不再能识别特定自然人，不再构成个人信息** |
| 《个人信息保护法》第73条 | 匿名化：个人信息经过处理无法识别特定自然人且不能复原的过程 | 本流程的K-匿名（k≥5）+ 脱敏 + 差分隐私组合满足匿名化要求 |
| 《个人信息保护法》第28条 | 敏感个人信息包括医疗健康、金融账户等信息 | 高敏感病种（四川L4）与基因信息（四川L5）已被完全剔除；一般健康数据经匿名化后不再构成敏感个人信息 |
| 《网络安全法》第42条 | 网络运营者不得泄露、篡改、毁损其收集的个人信息；未经被收集者同意，不得向他人提供个人信息。但是，经过处理无法识别特定个人且不能复原的除外 | **关键条款**：经匿名化处理后的数据不受此条限制 |

### 2.2 地方标准支撑（DB51/T 2989—2023）

四川省地方标准《健康医疗大数据应用指南》明确给出了数据分级与应用前置条件的对应关系：

| 数据等级 | 内容 | 应用前置条件 | 本流程处理 |
|---|---|---|---|
| **第1级** | 不包含第2~5级内容的数据（如脱敏后的病历） | **无前置条件** | ✓ 脱敏匿名后数据降至本级 |
| **第2级** | 机构运营数据（门诊人次、药品消耗等） | 相关机构授权同意 | ✓ 获取政府授权 |
| **第3级** | 敏感个人信息（身份证、手机号等） | 相关主体授权同意（公共服务目的除外） | ✓ 经脱敏/K-匿名后降级 |
| **第4级** | 敏感病种（HIV、精神病等） | 严格主体授权 | ✗ **完全剔除，不进入流程** |
| **第5级** | 个人遗传信息 | 主体授权+部门审批 | ✗ **完全剔除，不进入流程** |

**关键结论**：DB51/T 2989—2023 附录 A 明确规定，第3级数据经去标识化处理后（采用"屏蔽、假名、泛化、K-匿名、差分隐私"等技术），可降级为第1级数据，第1级数据的应用**无前置条件限制**。

### 2.3 国家标准支撑

| 标准 | 核心要求 | 本流程对应 |
|---|---|---|
| GB/T 37964《个人信息去标识化指南》 | 去标识化后应进行重标识风险评估 | 本流程 K≥5 + L-多样性 + 差分隐私组合，重标识风险极低 |
| GB/T 39725《健康医疗数据安全指南》 | 健康医疗数据应按级别采取不同安全措施 | 本流程严格按 L1~L5 分级路由 |
| GB/T 43697-2024《数据分类分级规则》 | 衍生数据（经统计、去标识化加工后的数据）可重新定级 | 脱敏匿名后的数据属于衍生数据，可降至一般数据 |

## 三、核心合规论证

### 3.1 论证一：发送到大模型的数据已不构成"个人信息"

**法律定义**（《个人信息保护法》第4条）：
> 个人信息是以电子或者其他方式记录的与已识别或者可识别的自然人有关的各种信息。

**本流程处理后的数据状态**：

| 原始字段（L3） | 处理手段 | 处理后结果 | 是否可识别个人 |
|---|---|---|---|
| 身份证号 11010119900101123X | 掩码脱敏 | 110\*\*\*\*\*\*\*\*\*\*\*123X | ✗ 不可 |
| 手机号 13800138000 | 掩码脱敏 | 138\*\*\*\*8000 | ✗ 不可 |
| 姓名 张三 | 哈希加盐 | a3f5c8e2... | ✗ 不可 |
| 年龄 68 | K-匿名泛化 | [60-70] | ✗ 不可 |
| 邮编 610041 | K-匿名前缀 | 610\*\*\* | ✗ 不可 |
| 诊断 高血压 | 语义泛化 | 心血管类慢病 | ✗ 不含个人标识 |
| 诊断 2型糖尿病 | 语义泛化 | 代谢类慢病 | ✗ 不含个人标识 |
| 用药记录 氨氯地平5mg | 语义泛化 | 降压类药物 | ✗ 不含个人标识 |
| HIV诊断 B21.1 | **完全剔除** | —（不进入流程） | — |

**结论**：经过脱敏 + K-匿名（k≥5）+ 差分隐私组合处理后，任何单条记录均无法识别或关联到特定自然人。根据《个人信息保护法》第73条，该数据已完成"匿名化"，**不再属于个人信息**，不受个人信息保护相关条款约束。

### 3.2 论证二：DB51/T 2989—2023 明确支持本场景

四川省标准在附录 D"健康医疗大数据应用的典型场景"中，明确列出了**"智慧医养、智慧养老"**场景：

| 场景 | 数据分级 | 前置条件 | 数据共享方式 | 数据处理方式 |
|---|---|---|---|---|
| **智慧医养、智慧养老** | 第3级 | 数据脱敏后相关部门授权 | 数据资源池 | 信任共享 |

本流程的业务目标——"利用医疗数据为老人提供康养建议"——**完全对应**该标准中"智慧医养、智慧养老"的典型应用场景。标准明确允许：
1. 使用第3级数据；
2. 经脱敏处理后；
3. 获得相关部门授权；
4. 以信任共享方式提供数据。

此外，标准 5.3.1.3 条明确将"智慧康养、慢病管理、老年保健"列为**公共医疗卫生服务—医疗卫生辅助服务**的合法应用目的。

### 3.3 论证三：高敏感数据被精确隔离，一般健康数据经保护后合规使用

本流程在分类分级阶段进行**精细化筛选**，而非简单地剔除所有医疗数据：

**完全剔除的数据（四川L4/L5等价）：**
- **四川L4 敏感病种**：HIV（ICD-10 B20-B24）、精神分裂症（F20-F29）、癌症（C00-C97）等——不进入后续任何处理环节；
- **四川L5 基因信息**：BRCA1/TP53 基因、SNP、基因测序数据等——不进入后续任何处理环节。

**保留并经脱敏后使用的数据（一般健康状况）：**
- 常见慢病诊断：高血压、糖尿病、冠心病等（经K-匿名泛化为“慢病类型”）；
- 用药信息：降压药、降糖药等（经泛化为“用药类别”）；
- 基本体征：年龄、性别、BMI区间等（经K-匿名泛化）。

**合规依据：**
- 四川L4/L5的剔除满足 DB51/T 2989—2023 附录A对第4、5级数据“严格控制使用范围”“数据不出域”的要求；
- 一般健康数据（高血压、糖尿病等）在四川标准中属于**L3级**（基础诊疗记录），标准明确允许经脱敏后使用；
- 即使在广东标准中，这类数据属于第4级“个人健康状况”，但经去标识化处理后同样满足共享要求（详见第七章）。

### 3.4 论证四：去标识化技术满足国标要求

DB51/T 2989—2023 第 5.4.2.3.3 条对第3级数据的技术指南：

> 对第 3 级数据，宜按照 GB/T 37964 的相关要求采用**抑制、屏蔽、泛化、加密、假名化、K-匿名模型**等技术开展去标识化工作。

本流程采用的技术手段**完全覆盖**标准要求：

| 标准要求技术 | 本流程实现 | 对应模块 |
|---|---|---|
| 抑制 | 删除无法满足 k-匿名的记录 | K-Anonymity 模块 |
| 屏蔽 | 身份证号/手机号掩码 | Masking 模块 |
| 泛化 | 年龄→区间、邮编→前缀 | K-Anonymity 泛化 |
| 加密 | 哈希加盐（SHA-256+Salt） | Masking 模块 |
| 假名化 | Token化映射 | Masking 模块 |
| K-匿名模型 | k≥5，L-多样性（L≥2） | K-Anonymity 模块 |
| 差分隐私 | Laplace 机制（ε≤1.0） | DP 模块 |

### 3.5 论证五：全流程满足"安全可控"与"全程监管"原则

DB51/T 2989—2023 总体原则要求：

| 原则 | 要求 | 本流程实现 |
|---|---|---|
| **安全可控**（4.6） | 通过安全技术手段，尽可能在不提供原始数据的情况下满足应用需求 | 原始数据不出域，仅发送脱敏匿名后的衍生数据 |
| **全程监管**（4.7） | 事前评估审核、事中实时监管、事后评价反馈；全程透明、留痕 | 审计日志记录 who/when/what/params/proof；隐私预算台账 |
| **分类分级**（4.3） | 建立数据安全等级和数据类别权限分级 | 三层漏斗式分类引擎（Rule→NER→LLM），字段级/记录级/表级标签 |
| **一事一议**（4.4） | 以共享满足应用目标的最少数据项、最少数据量为原则 | 仅发送康养建议所需的最小字段集 |

## 四、"所有数据都不能出域"观点的回应

### 4.1 该观点的合理关切

"不分等级所有数据都不能发送到外部大模型"这一立场，其合理关切在于：
- 担心原始敏感医疗数据泄露；
- 担心患者隐私被侵犯；
- 担心违反数据安全法规。

**我们完全认同这些关切**，这也是本流程设计分类分级 + 隐私处理 + 审计体系的原因。

### 4.2 该观点的法律误区

然而，"所有数据都不能出域"这一绝对化表述**缺乏法律依据**：

| 误解 | 法律事实 |
|---|---|
| "医疗数据一律不能出域" | 《个人信息保护法》第73条：匿名化后的数据不再是个人信息，不受个保法约束 |
| "政府数据一律不能共享" | 《数据安全法》第42条：国家推动公共数据开放共享；DB51/T 2989 明确"共享为常态，不共享为例外" |
| "L3数据不能给第三方" | DB51/T 2989 附录D：智慧养老场景明确允许L3数据脱敏后以信任共享方式提供 |
| "调用大模型等于数据泄露" | 发送的是脱敏匿名后的衍生数据（L1级），不含任何可识别个人的信息 |

### 4.3 类比说明

| 场景 | 是否合规 | 原因 |
|---|---|---|
| 将患者完整病历（含姓名、身份证、HIV诊断）发给大模型 | ✗ 违规 | 包含L3 PII + L4敏感病种，未做任何处理 |
| 将脱敏后的"60-70岁男性，高血压，用药记录"发给大模型获取康养建议 | ✓ 合规 | 已匿名化，不可识别个人，属于L1级衍生数据 |
| 将统计级数据"某社区高血压患病率32%"发给大模型分析 | ✓ 合规 | 群体统计数据，不涉及任何个人 |

本流程属于后两种情况，**发送的数据在数学上已无法关联到任何特定个人**。

## 五、技术保障措施

### 5.1 分类分级引擎

采用三层漏斗式检测架构，确保敏感数据零遗漏：

```
第一层：声明式规则引擎（微秒级）
  → 正则匹配身份证/手机号/银行卡
  → ICD-10 编码区间匹配敏感病种
  → 基因字段关键词匹配

第二层：Small-NER 模型（毫秒级）
  → 医疗命名实体识别
  → 隐式敏感信息捕获

第三层：本地 VLM/LLM（秒级，旁路）
  → 多模态手写病例识别
  → 100% 本地执行，不向外部发送
```

### 5.2 隐私处理参数

| 数据等级 | 处理策略 | 参数 | 处理后等级 |
|---|---|---|---|
| L3（PII） | 脱敏 + K-匿名 + DP | mask, k=5, L=2, ε=1.0 | → L1/L2 |
| L4（敏感病种） | **完全剔除** | — | 不进入流程 |
| L5（基因信息） | **完全剔除** | — | 不进入流程 |

### 5.3 审计与可追溯

每次数据处理操作记录：
- **Who**：操作者身份
- **When**：时间戳
- **What**：处理原语类型（脱敏/K-匿名/DP）
- **Params**：实际生效参数快照
- **Proof**：K/L/T 验证结果、信息损失率、抑制记录数
- **Budget**：隐私预算消耗（ε 累计）

### 5.4 大模型调用安全

| 措施 | 说明 |
|---|---|
| 数据最小化 | 仅发送康养建议所需的最小字段集 |
| 查询混淆 | 在真实查询外注入 dummy queries，隐藏真实意图 |
| TLS 加密传输 | 全链路 HTTPS/TLS 1.3 |
| 结果审核 | 大模型返回内容为通用康养建议，不含个人数据 |
| 无回传 | 大模型不向第三方回传输入数据（选择合规大模型服务商） |

## 七、广东省标准符合性分析（T/GDWJ 013—2022）

> 本节论证本流程同时符合广东省团体标准《健康医疗数据安全分类分级管理技术规范》（T/GDWJ 013—2022），为跨省业务拓展提供合规依据。

### 7.1 广东省标准分级体系与本流程的映射

广东省标准采用**四级分级体系**（1~4级），与四川省五级体系并非简单一一对应。本流程的剔除策略是：**以四川L4/L5为基准，剔除广东L4中的高敏感子集，保留一般健康状况数据并经脱敏后使用**。

| 广东标准级别 | 数据内容（附录B） | 本流程处理 | 说明 |
|---|---|---|---|
| **第4级**（最高） | 个人身份信息（身份证、社保卡） | ✗ **完全剔除** | 等价四川L3 PII，但本场景无需使用 |
| | 个人生物识别信息（基因、指纹、虹膜） | ✗ **完全剔除** | 等价四川L5，绝对禁止出域 |
| | 个人健康状况——**敏感病种**（HIV、精神病、癌症等） | ✗ **完全剔除** | 等价四川L4，严格禁止出域 |
| | 个人健康状况——**一般慢病**（高血压、糖尿病、冠心病等） | ✓ **保留，脱敏+K-匿名+DP后使用** | 四川标准中属L3（基础诊疗），经去标识化后合规使用 |
| | 保险信息 | ✗ **完全剔除** | 本场景无需使用 |
| **第3级** | 住院医嘱、检查检验报告、病程记录、手术记录、医疗交易信息 | ✓ 脱敏+K-匿名+DP后降级 | 仅提取康养相关字段 |
| **第2级** | 用药信息（药物用法、剂量、频率） | ✓ 轻量脱敏后使用 | 泛化为“用药类别” |
| **第1级** | 医院基本数据、传染病疫情统计、疾病预防数据 | ✓ 直接使用 | 统计级数据，无个人标识 |

**关键说明：广东L4“个人健康状况”的精细化处理**

广东标准将“个人健康状况”（主诉、病史、家族史等）整体定为第4级，但本流程并非将其全部剔除，而是进行**字段级精细化拆分**：

```
广东L4“个人健康状况”数据
    │
    ├─── 敏感病种诊断（HIV、精神病、癌症等）
    │     → 等价四川L4 → ✗ 完全剔除
    │
    ├─── 基因/遗传信息
    │     → 等价四川L5 → ✗ 完全剔除
    │
    └─── 一般健康状况（高血压、糖尿病、冠心病、关节炎等）
          → 四川标准中属L3（基础诊疗记录）
          → ✓ 保留，经脱敏+K-匿名+DP后使用
          → 泛化示例：“高血压”→“心血管类慢病”
```

这一精细化处理的合规性在于：
1. 四川标准明确将“基础诊疗记录”定为L3，允许经脱敏后使用；
2. 广东标准附录F第5条b1)允许第2/3级数据“脱敏后再共享”；
3. 广东标准第7.1条d)规定“在使用数据或披露前，应采用数据脱敏技术”——本流程对保留的健康数据严格执行脱敏；
4. 康养建议场景**必须**知道老人的常见慢病类型才能生成有效建议，这属于“最小必要”原则的合理范围。

### 7.3 广东省标准下的核心合规论证

**论证一：第4级数据中的高敏感子集执行了最严格的保护**

广东省标准附录F第5条b2)对第4级数据要求“**只允许进行可用不可见的共享**”。本流程对第4级数据中的高敏感子集（个人身份信息、生物识别信息、敏感病种诊断、基因信息、保险信息）采取的措施是**完全剔除**——比“可用不可见”更为严格，从根本上消除了这些数据泄露的可能性。

**论证二：第4级中保留的一般健康数据满足“脱敏后再共享”要求**

对于第4级“个人健康状况”中保留的一般慢病数据（高血压、糖尿病等），本流程执行了与第3级数据同等甚至更严格的去标识化处理：
- 自动识别：三层漏斗引擎（Rule→NER→LLM）确保敏感病种零遗漏剔除；
- 脱敏处理：掩码、哈希加盐、K-匿名泛化、差分隐私加噪四重保护；
- 语义泛化：具体诊断泛化为疾病大类（如“高血压”→“心血管类慢病”）；
- 降级确认：处理后数据经重标识风险评估，确认降至第1/2级后方可出域。

这满足广东标准附录F第5条b1)“识别出敏感数据并对其进行脱敏后再共享”的要求，也满足第7.1条d)“在使用数据或披露前，应采用数据脱敏技术”的规定。

**论证三：满足"去标识化"法定要求**

广东省标准第7.1条b)规定："原则上未经过脱敏处理的数据不可降级使用"。本流程严格执行"先脱敏、后降级、再使用"的顺序，且降级操作记录在审计日志中，满足全过程审计要求。

**论证四：满足最小权限与数据最小化**

广东省标准附录E第4条c)要求"应赋予操作主体最小操作权限和最小数据集"。本流程仅向大模型发送康养建议所需的最小字段集（如年龄段、慢病类型、用药类别），不发送任何可识别个人的字段。

## 八、结论

### 8.1 合规性总结

本流程在以下维度均满足合规要求：

| 维度 | 合规状态 | 依据 |
|---|---|---|
| 数据分类分级 | ✓ 合规 | DB51/T 2989—2023 第5.2.2条、T/GDWJ 013 第6章、GB/T 43697-2024 |
| 高敏感数据隔离 | ✓ 合规 | 四川L4/L5完全剔除；广东4级中高敏感子集完全剔除（比“可用不可见”更严格） |
| 去标识化处理 | ✓ 合规 | DB51/T 2989 第5.4.2.3.3条、T/GDWJ 013 附录F第4/5条、GB/T 37964 |
| 匿名化法律效果 | ✓ 合规 | 《个人信息保护法》第73条 |
| 应用场景合法性 | ✓ 合规 | DB51/T 2989 附录D"智慧医养、智慧养老" |
| 应用目的合法性 | ✓ 合规 | DB51/T 2989 第5.3.1.3条"医疗卫生辅助服务" |
| 全流程审计 | ✓ 合规 | DB51/T 2989 第4.7条、T/GDWJ 013 附录E第6条（日志≥6个月） |
| 数据最小化 | ✓ 合规 | DB51/T 2989 第4.4条、T/GDWJ 013 附录E第4条c)最小数据集 |
| 传输安全 | ✓ 合规 | T/GDWJ 013 附录F第2条（TLS密码技术） |
| 监测溯源 | ✓ 合规 | T/GDWJ 013 附录E第7条（实时监控+追踪溯源） |

### 8.2 核心结论

> **经过严格分类分级（剔除四川L4敏感病种与L5基因信息等价子集）→ 对保留的一般健康数据执行脱敏匿名处理（K-匿名k≥5 + 掩码 + 差分隐私 + 语义泛化）后，数据在法律上已完成“匿名化”，不再构成《个人信息保护法》所定义的“个人信息”。将该等数据发送至外部大模型获取通用康养建议，不违反《数据安全法》《个人信息保护法》、DB51/T 2989—2023（四川）及 T/GDWJ 013—2022（广东）的任何条款。**

### 8.3 建议补充的合规动作

为进一步增强合规可信度，建议在项目实施前完成：

1. **专家评估**：由数据控制方（卫健委）组织专家组出具评估意见（参照 DB51/T 2989 附录C）；
2. **数据使用协议**：与数据控制方签订正式协议，明确数据范围、处理方式、责任边界；
3. **伦理审查**：提交伦理委员会审查（虽非强制，但增强公信力）；
4. **大模型服务商合规审查**：确认所选大模型（DeepSeek/千问）的数据安全协议，确保不将输入数据用于模型训练；
5. **定期审计**：每季度对分类分级准确率、脱敏有效性、审计日志完整性进行复核。
